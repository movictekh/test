# MSW Development Startup and Stage 2 Sign-off

## Startup problem

The previous boot path mixed `worker.start()`, stale-worker unregistration,
a timeout race, and continuing without MSW. That is unsafe because MSW is the
development API backend.

A timeout does not cancel the already-running `worker.start()` promise.
Unregistering the worker from that timeout path can race the startup operation.

## Final startup rule

```text
validate environment
→ import MSW worker
→ start worker once
→ wait until interception is ready
→ mount React
```

There is no unregister-on-every-start behavior.

If MSW is not ready within the bounded startup window, React is not mounted.
A visible development startup error is shown instead of a blank page or a
half-working app without mocks.

The worker URL uses `import.meta.env.BASE_URL`.

## One-time browser recovery

After replacing the old boot code, an existing browser tab can still hold the
old registration. Clean it once:

```text
DevTools
→ Application
→ Service Workers
→ Unregister mockServiceWorker.js
→ Reload http://localhost:5173
```

Do not add automatic unregister logic back to normal application startup.

## Worker maintenance

`public/mockServiceWorker.js` is generated by MSW. Do not edit it manually.

After upgrading `msw`, regenerate it with:

```bash
npx msw init public --save
```

## Stage 2 sign-off

The Stage 2 runtime flow is complete:

- submitted quotations create pending approval records;
- duplicate pending approvals are prevented;
- `/app/approvals` is the authoritative approval UI;
- quotation files do not expose a competing Approve action;
- approval decisions synchronize quotation state;
- accepted quotations create invoices;
- payments update invoice balances and collection state.

Regression coverage now includes approval-queue semantics.

Final automated gate:

```bash
npm run check
npm run build:storybook
```
